# Сверка списаний по декларациям

Пример показывает, как сверить учётный реестр с отчётом таможни по полному номеру декларации. Обе учебные таблицы лежат в [input.json](input.json). Исходные суммы по пяти декларациям приведены ниже. Номера, плательщик, даты и коды платежей условные. В дополнительных сценариях меняется по одному условию. Все суммы в JSON указаны в копейках.

| Последние цифры номера декларации | Реестр, ₽ | Отчёт, ₽ | Отчёт минус реестр, ₽ | Что показала сверка |
| --- | ---: | ---: | ---: | --- |
| 0000001 | 12 500 | 12 500 | 0 | Суммы совпадают |
| 0000002 | 7 500 | 7 200 | −300 | Недостающая сумма в отчёте относительно реестра |
| 0000003 | 10 000 | 10 300 | +300 | Сумма в отчёте выше учётной |
| 0000004 | 2 300 | — | −2 300 | Строка только в реестре |
| 0000005 | — | 2 300 | +2 300 | Строка только в отчёте |

При одинаковых реквизитах движения и разных номерах строк группа уходит на проверку. Если различаются номера строк и коды бюджетной классификации, при отсутствии других причин ручной проверки обе суммы участвуют в сверке. В проверке B5 две записи по 6 250 ₽ с разными кодами и номером `ФТС-01` останавливают расчёт при сходящихся контрольных итогах. Отчёт сохраняет обе записи со всеми реквизитами в `duplicate_source_rows`. Отдельный сценарий проверяет повтор номера строки учётного реестра в записях по разным декларациям.

Корректировка с полным номером декларации помечает связанную группу и сохраняет номер исходной строки. При пустой, отсутствующей или обрезанной ссылке все группы получают отметку о ручной проверке. Строка корректировки выделяется отдельно, арифметические разницы сохраняются. Если полный номер относится к декларации вне выборки, исходная строка выводится отдельно с сохранением статусов сравниваемых групп.

В проверке B6 неизвестное движение в 500 ₽ входит в исходящий контрольный итог в 32 800 ₽. Строка с исходными реквизитами остаётся в `unrecognized_movement_rows`. Все группы получают `manual_review` с причиной `unrecognized_movement` и прежней разницей в копейках. В парном сценарии распознанный залог в 500 ₽ выводится в `out_of_scope_rows` и сохраняет исходные статусы групп. В отчёте о прогоне `manual_review` означает ручной разбор, `stopped` означает остановку до сопоставления.

Для B7 поле `coverage_confirmed: true` означает, что бухгалтер подтвердил полноту реестра для всего выбранного среза. Если подтверждены только отдельные декларации, их полные номера перечисляются в `coverage_confirmed_declarations`. Группы за пределами подтверждённого охвата получают `manual_review` с причиной `ledger_coverage_unconfirmed`. Если подтверждений нет, отметку получают все группы. Суммы, разницы и номера исходных строк сохраняются. В базовом сценарии по первой декларации сверка подтверждает равенство сумм по 12 500 ₽. При том же наборе строк с неизвестной полнотой совпадение заменяется ручной проверкой. После восстановления отдельной проводки на 500 ₽ в реестре видно 13 000 ₽ против 12 500 ₽ в отчёте ФТС. Разница составляет −500 ₽, обе учётные строки сохранены для разбора.

## Повторение

Откройте папку с распакованными файлами и выполните команду в терминале. Нужен Python 3.12 со стандартной библиотекой.

```powershell
python reconcile.py --verify
```

Команда проверяет ожидаемые суммы, статусы и исходные строки в 22 сценариях и сравнивает полный результат с [result.json](result.json). Для построения отчёта заново запустите ту же команду без `--verify`.

## Границы примера

Метки «ДТ», «КДТ», «решение о возврате» и «залог» обозначают уже распознанные типы операций. Каждой строке в своей таблице присваивают уникальный номер из источника. При подготовке бухгалтер сверяет полноту учётного реестра и связь корректировки или возврата с декларацией по первичному документу. При установленной связи вход содержит полный номер декларации, при неопределённой поле оставляют пустым. Скрипт проверяет формат ссылки. Два контрольных итога выявляют потерю денежных сумм, если она изменила итог. Совпадение по декларации относится к сумме первоначальных списаний в заданном срезе. Расхождения между отдельными видами платежей внутри декларации могут компенсироваться. Пример ограничен подготовленными условными таблицами.
